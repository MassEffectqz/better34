## 🔍 ПОЧЕМУ НЕ ИСПРАВЛЕНЫ СРАЗУ — ПОДРОБНО

### Q-1: Глобальные синглтоны `GetDB()` / `GetConfig()` / `GetAccounts()` — `internal/`
- **Что сейчас:** `sync.Once` + глобальные переменные (`config.go:40-44` и аналогично в `database.go`, `accounts.go`). 50+ файлов вызывают `internal.GetConfig()` напрямую.
- **Почему не исправлено:** рефакторинг = внедрение зависимостей (DI) через конструкторы: переписывание сигнатур хендлеров, моки в юнит-тестах, правка 50+ файлов. HTTP API не ломается, но ломается совместимость кода — любой форк/PR с правками в `internal/` конфликтует полностью.
- **Поэтапно:** (1) хендлеры принимают `*Config` параметром; (2) тесты на `t.TempDir()`; (3) в конце — удалить глобали.

### Q-2: Один большой пакет `internal` с 50+ Go-файлами
- **Что сейчас:** все хендлеры, база, загрузчик, DoH, pHash, Ollama, SSE — в одном Go-пакете: общие имена, нулевая инкапсуляция.
- **Почему не исправлено:** разбивка на под-пакеты (`internal/db`, `internal/dl`…) требует перестройки импортов во всех файлах одновременно (Go не мигрирует пакеты частично), а циклы импорта часто выявляются только компиляцией. «Наполовину» этот шаг не сделать.
- **Поэтапно:** сначала листовые пакеты без зависимостей (`phash`, `doh`), затем база, затем хендлеры.

### Q-3: Непоследовательная обработка ошибок
- **Что сейчас:** часть ошибок логируется через `slog`, часть молча игнорируется, часть возвращается клиенту в разных форматах.
- **Почему не исправлено:** единый helper (`respondErr(c, status, code, msg)`) меняет **тела HTTP-ответов** — `static/js/api.js` парсит `err.message`; переименование полей реально ломает UI. Нужен проход по ~120 хендлерам с ручным тестом сценариев.
- **Поэтапно:** helper → замена по группам эндпоинтов → `api.js` нормализует оба формата.

### Q-4: Частичная валидация ввода на эндпоинтах
- **Что сейчас:** часть эндпоинтов проверяет длину/тип, часть принимает любые JSON-поля.
- **Почему не исправлено:** строгая валидация (лимиты, whitelist полей) = **отказ в старых легитимных запросах** — включая оффлайн-очередь `offline.js`, которая отправляет тела, собранные раньше. Ломает совместимость в момент внедрения; нужен согласованный релиз UI + сервера.
- **Поэтапно:** валидационный слой по группам; оффлайн-очередь фильтровать до постановки.

### PB-7: `buildMediaHTTPClient()` без общего таймаута — `internal/handlers_media.go`
- **Что сейчас:** per-request таймауты есть, общего `http.Client.Timeout` нет — при молчащем CDN соединение может висеть.
- **Почему не исправлено:** общий `Timeout` обрежет **легитимные длинные загрузки** больших видео. Нужен `context.WithTimeout` per-file (по размеру/типу), а не на транспорт — иначе ломается сценарий «медленная, но успешная» загрузка.

### PB-8: Токен в query для SSE (`/api/events?token=`) — `internal/accounts.go:64`
- **Что сейчас:** `TokenMatches()` принимает `?token=` **только для `/api/events`**, потому что `EventSource` не умеет заголовки (`state.js:988`). Cookie-auth есть (httpOnly `briefly_session`), но legacy-режим (BRIEFLY_TOKEN, один пользователь на удалённом хосте) без cookie.
- **Почему не исправлено:** убрать `?token=` = сломать legacy-режим удалённого доступа — главный сценарий развертывания. Альтернатива — одноразовый short-lived ticket (POST `/api/sse-ticket`) для открытия EventSource: **новый эндпоинт + согласованный релиз UI**, т.е. редизайн аутентификации.
- **Риск сейчас низкий:** query только на собственном access-логе сервера (не прокси).

### S-3: Нет Content-Security-Policy — `middleware.go:234-256`
- **Что сейчас:** `webSecurityMiddleware()` ставит `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` и `Content-Security-Policy-Report-Only` при `BRIEFLY_DEBUG=1` (политика совпадает с мета-CSP в `index.html`). Нарушения видны в консоли браузера.
- **Почему не enforcing сразу:** строгий CSP требует тщательно подобранный whitelist: медиа идёт через `/api/proxy` с CDN-хостов rule34 и прочих, превью — `data:`/blob, sw.js кэширует. Ошибка в whitelist = чёрный экран у всех пользователей. Inline-скрипты в проекте почти отсутствуют (один `<script type=module>`, без inline-обработчиков).
- **Поэтапно:** сначала report-only (сделано в debug), мониторить нарушения, потом enforcing для всех — отдельным изменением.

### S-4: API доступен без TLS redirect — `main.go` / `tls.go`
- **Что сейчас:** сервер слушает HTTP и HTTPS параллельно (HTTP/3 рекламируется alt-Svc). В TLS-режиме plain-HTTP на том же порту редиректится на HTTPS (черновик демкса). При `BRIEFLY_FORCE_HTTPS=1` отвеченным по TLS запросам ставится `Strict-Transport-Security` (HSTS) — клиенты запоминают HTTPS.
- **Почему не полностью:** автоматический принудительный `301 https://` для `/api/*` в HTTP-only режиме создаст **бесконечный цикл редиректов** за reverse-proxy (nginx/caddy уже отдают TLS наружу) и сломает локальных HTTP-пользователей. Полный enforcing — отдельным флагом, чтобы не сломать 3 сценария развертывания сразу.
- **Риск снижен:** cookie уже `Secure` в HTTPS-режиме, CSRF-middleware блокирует кросс-сайтовые запросы.
